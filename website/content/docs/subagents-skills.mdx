<Callout type="warn" title="On main, coming in 3.0.0a4">
  Not in a published package yet. `runtime/adk@1.5.0` runs sub-agents and loads instruction-pack
  skills. Run end to end on macOS with Docker Desktop and Gemini on 2026-11-19: one agent with two
  sub-agents (one with a tool), and one with two skills, each released through the eval gate, plus
  Northwind 61/61 on the same runtime. Script skills are not built, and no other runtime, provider
  or Linux has been run. On older runtimes `build` refuses both (`RUNTIME_NO_SUBAGENTS`,
  `RUNTIME_NO_SKILLS`).
</Callout>

Sub-agents are specialist agents the main agent calls as tools; skills are instruction packs it loads when needed. Pin `runtime: runtime/adk@1.5.0` to run them.

## Sub-agents

```yaml
# agent.yaml
subagents:
  - name: billing                 # the agent calls it as the tool ask_billing
    description: "Refunds, invoices and payment questions."
    model: {alias: billing-model, max_model_calls: 4}
    prompt: {ref: prompt/billing-specialist@1.1.0}
    tools: [{ref: tool/refund-request@1.0.0}]
    max_calls_per_turn: 2
limits:
  turn_model_calls: 12            # every agent together
```

Sub-agents run in the same container, turn and deployment as the agent, which always writes the
reply. Each sees only the request the agent writes, never the conversation or the customer's
notes. The rules `validate` and `build` check:

- At most 5, depth 1 (`SUBAGENT_DEPTH`).
- One gateway key for the deployment: no `budget_usd` or `rpm` on a sub-agent
  (`SUBAGENT_FIELD_UNSUPPORTED`), and the gate denies a sub-agent alias the environment doesn't
  allow.
- No customer-notes tool (`SUBAGENT_NOTES`), and MCP tools only from the agent's own grant
  (`SUBAGENT_MCP_UNGRANTED`).
- `ask_<name>` may not clash with another tool name (`SUBAGENT_NAME_CLASH`).

Tool separation is not isolation: all tool code runs in one process with the deployment's
privileges.

## Skills

```sh
agentbreeder registry new skill refund-policy [--scripts]
```

```yaml
# agent.yaml
skills: [{ref: skill/refund-policy@1.0.0}]    # at most 10
```

A skill version holds `manifest.yaml`, a `SKILL.md` with strict front matter, optional
`references/` and, for a script skill, declared `scripts/`. A version with scripts is code, and
the CLI and console say so before importing it. `runtime/adk@1.5.0` lists each skill's
description in every turn and loads its `SKILL.md` when the model asks (`load_skill`); the
agent's own event log records each load with the skill's hash. A skill with scripts is refused
(`RUNTIME_NO_SKILL_SCRIPTS`): no runtime runs a script.

## Evals for both

Eval cases accept `subagents_include`, `subagents_exclude`, `subagent_tools_include`,
`skills_loaded` and `skills_not_loaded`, read from the reply `runtime/adk@1.5.0` sends; on another
runtime a case using them fails, never passes. Cases can carry `tags`, and `eval` and `release`
print a pass rate per tag. In the recorded run, a deliberately wrong routing case failed the gate.

## Cost and the console

`agentbreeder cost --by subagent` splits each deployment's LLM cost by sub-agent, from the tag
the runtime puts on each model call. In the recorded run it matched LiteLLM's spend rows
exactly. In the [console](/docs/command-center), Try it shows which sub-agents and skills a
reply used.
