Every example in `examples/` is a deployable agent with a real `agent.yaml` and runnable code.
Clone the repo and run any example locally in under 5 minutes.

```bash
git clone https://github.com/agentbreeder/agentbreeder
cd agentbreeder/examples/<example-name>
agentbreeder deploy --target local
```

> **Status:** Deploy-target availability (which targets ship full governance, greenfield provisioning, and secret auto-mirror) is maintained in one canonical place — see the [deploy-target status table](cli-reference#agentbreeder-deploy).

## Cloud Target Examples

Use these to see how the same agent deploys to a specific cloud.

### AWS App Runner
**`examples/aws-app-runner-agent/`**

Deploys to AWS App Runner — serverless containers with no VPC, no ALB, and no load balancer configuration required. Ideal for simple HTTP-accessible agents.

*Prereq:* AWS ECS Fargate ships full governance; greenfield provisioning is available via `agentbreeder deploy --provision`, otherwise deploys use existing infra plus auto-provisioned data backends. On AWS, pre-create secrets in Secrets Manager (auto-mirror is on the roadmap). See the [deploy-target status table](cli-reference#agentbreeder-deploy).

```yaml
# agent.yaml
deploy:
  cloud: aws
  runtime: app-runner
  region: us-east-1
```

```bash
cd examples/aws-app-runner-agent
agentbreeder deploy --target app-runner --region us-east-1
```

---

### Claude Managed Agents (Anthropic)
**`examples/claude-managed-agent/`**

Deploys to Anthropic's managed cloud — no container build, no infrastructure to provision. Anthropic manages the execution environment. Requires `deploy.cloud: claude-managed` and Claude 4.5+ model.

```yaml
# agent.yaml
deploy:
  cloud: claude-managed

claude_managed:
  environment:
    networking: unrestricted
  tools:
    - type: agent_toolset_20260401
```

```bash
cd examples/claude-managed-agent
agentbreeder deploy --target claude-managed
```

<Callout type="info">
  Claude Managed Agents requires a direct Anthropic API key — AWS Bedrock and GCP Vertex AI are not supported for this target.
</Callout>

## Local Model Examples

Run agents with no API keys required.

### Ollama (Local LLMs)
**`examples/ollama-agent/`**

Runs a full agent locally using Ollama and any GGUF-compatible model (Gemma, Llama, Mistral, Phi). No API key needed.

```bash
# Pull a model first
ollama pull gemma3

cd examples/ollama-agent
agentbreeder deploy --target local
```

```yaml
# agent.yaml
model:
  primary: ollama/gemma3
  gateway: ollama

deploy:
  cloud: local
  runtime: docker
```

---

### OpenRouter (300+ models, one API key)
**`examples/openrouter-agent/`**

Routes to DeepSeek-R1, Llama 3, Mistral, or 300+ other models via OpenRouter. One `OPENROUTER_API_KEY` instead of per-provider keys.

```yaml
# agent.yaml
model:
  primary: openrouter/deepseek/deepseek-r1
  gateway: openrouter
```

```bash
agentbreeder provider add openrouter --api-key <your-key>
cd examples/openrouter-agent && agentbreeder deploy --target local
```

## Real-World Agent Examples

### AI News Digest
**`examples/ai-news-digest/`**

Production-quality agent that runs as a daily digest:
1. Fetches top stories from Hacker News, ArXiv (cs.AI + cs.LG), and RSS feeds
2. Synthesises a grouped digest using Google ADK + Ollama Gemma3:27b
3. Emails the digest to configured recipients via Gmail

Demonstrates: MCP tool server, SMTP connector, Google ADK framework, Ollama local model.

```bash
cd examples/ai-news-digest

# One-time setup
agentbreeder setup

# Run now
agentbreeder chat --agent ai-news-digest

# Run as a daily daemon (fires at DIGEST_HOUR, default 8am)
python agent.py --schedule
```

## TypeScript SDK Examples

### Basic TypeScript SDK
**`examples/sdk-ts-basic/`**

Minimal TypeScript SDK example — define an agent with `@agentbreeder/sdk`, add tools and guardrails, print the generated `agent.yaml`.

```typescript
import { Agent, Tool } from "@agentbreeder/sdk";

const agent = new Agent("research-assistant", {
  version: "1.0.0",
  team: "engineering",
  framework: "claude_sdk",
})
  .withModel("claude-sonnet-4-6", { temperature: 0.7 })
  .withTool(searchTool)
  .withGuardrail("pii_detection")
  .withDeploy("aws", { runtime: "ecs-fargate" });

console.log(agent.toYaml());
```

```bash
cd examples/sdk-ts-basic
npm install && npm start
```

## Template Examples

**`examples/templates/`**

12 production-quality agent templates covering common enterprise use cases. Each is a complete `agent.yaml` with recommended model, tools, guardrails, and deploy config.

| Template | Use case |
|---|---|
| `support-triage` | Classify and route tier-1 support tickets (Zendesk + knowledge base) |
| `escalation-classifier` | Decide whether a support ticket needs immediate human escalation |
| `returns-processor` | End-to-end return and refund handling with PII protection |
| `github-pr-reviewer` | PR review for bugs, security, performance, and style with inline comments |
| `sql-analyst` | Natural-language questions to SQL, with plain-language explanations |
| `report-generator` | Daily BI digests from BigQuery / Snowflake posted to Slack |
| `market-researcher` | Market research reports from web, ArXiv, and news sources with citations |
| `competitor-monitor` | Weekly competitive-intelligence digest from competitor sites and news |
| `lead-qualifier` | Enrich and score inbound HubSpot leads |
| `invoice-processor` | Extract, validate, and route vendor invoices for approval |
| `incident-responder` | On-call runbooks, Slack war room, PagerDuty, and status-page drafts |
| `meeting-summarizer` | Meeting summaries with action items, Notion tasks, and Slack recaps |

Each template is a directory with an `agent.yaml` and a `README.md`. The folder also contains four single-file starters: `code-reviewer.yaml`, `customer-support-bot.yaml`, `data-analyzer.yaml`, and `research-assistant.yaml`.

```bash
cp -r examples/templates/support-triage my-support-agent
agentbreeder deploy my-support-agent/agent.yaml --target local
```
