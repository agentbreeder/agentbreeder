<Callout type="warn" title="Alpha preview: not a production release">
  These docs cover the `3.0.0a3` alpha preview. It runs on one machine, on local Docker and a local
  `kind` cluster, and is not a production release. A bare `pip install agentbreeder` still
  installs the older **2.x**, which is unmaintained and has known issues (see
  [Legacy 2.x](/docs/legacy-2x)), so [install](/docs/install) with the exact version. Don't point
  this release at 2.x `agent.yaml` files.

AgentBreeder takes an agent from an `agent.yaml` (or a container you already built) to a running
deployment on infrastructure you control. Every deploy passes an identity gate first, every
release passes an eval gate, and every attempt is written to a local audit log.

**Start here:** [Install](/docs/install) and run `quickstart`. Then
[Your own agent](/docs/your-own-agent), or let `agentbreeder new agent` and `agentbreeder next`
lead you.

## What works today

Each item below ran end to end on macOS with Docker Desktop, from a wheel built from `main`, a
checkout or an earlier preview. The published `3.0.0a3` itself has run `quickstart`, Northwind
from pip (61/61) and the console's sign-in only. Linux: install and `doctor` only.

- **[Build from agent.yaml](/docs/agent-yaml).** Describe an agent as versioned registry
  references (runtime, prompt, knowledge, tools, MCP servers, evals). `build` makes the image and
  the deploy manifest.
- **[Evals and release](/docs/evals).** `release` deploys a candidate, runs the eval set, and
  promotes the exact image only when it passes. Each release is kept as an `agent/<name>@X.Y.Z`
  package.
- **[Backing services](/docs/services).** `services up` starts Postgres with pgvector, a LiteLLM
  gateway, Phoenix and project services from `stack.yaml`.
- **[Models and gateway](/docs/models).** Gemini, OpenAI and OpenRouter, and Ollama on your own
  machine (on `runtime/adk@1.3.0` only), with budgets, rate limits and fallbacks on a per-deployment key.
- **[Guardrails](/docs/guardrails).** Presidio PII checks in the gateway, as an environment floor
  and per agent (real-Docker tests and one Northwind run; per-agent `deploy` is not yet run end to
  end).
- **[Cost](/docs/cost) and [traces](/docs/traces).** LiteLLM spend per deployment and model, and
  each turn's span tree from Phoenix.
- **[MCP tools](/docs/mcp).** MCP servers behind a relay that holds the credential and forwards
  only granted, pinned tools.
- **[Registries](/docs/registry).** Immutable versions you can show, diff, import, fork and edit.
- **[Identity gate](/docs/identity-gate).** A deploy is refused unless the agent exists in your
  identity provider with an active sponsor and the required grants. Optional Cedar, OPA or
  AuthZEN policy, second-person approval, a kill switch and a hash-chained audit log.
- **[Console](/docs/command-center)** (from `main`). `agentbreeder up` serves a local,
  single-user web UI that runs the same CLI commands.
- **[Kubernetes on kind](/docs/kubernetes)** (from `main` and `3.0.0a2`). Promote a released
  image to a local `kind` cluster.

On `main`, coming in 3.0.0a4 (not in a published package; macOS only):
[runtimes for LangGraph, the OpenAI Agents SDK, Deep Agents and CrewAI](/docs/runtimes) (Northwind
61/61 on each; only LangGraph's starter is verified), [sub-agents and
skills](/docs/subagents-skills) on `runtime/adk@1.5.0`, git [registry](/docs/registry) sources,
console password sign-in and notifications, and Kubernetes building blocks that have not run on a
real cluster ([Kubernetes on kind](/docs/kubernetes)).

## What isn't implemented

- Cloud or production deployment targets. Only local Docker and a local `kind` cluster.
- Authenticated invocation: a deployed agent's endpoint trusts whatever caller reaches it, so it
  is published on loopback only.
- A multi-user console or a versioned management API.
- Runtime enforcement beyond MCP Streamable HTTP tool calls through the opt-in egress sidecar.
- A production secret backend (local secret files only).

The identity gate's live checks so far use the static-file adapter; the Entra, Keycloak, Okta
(experimental) and AWS adapters are fixture-tested.

## Install

Requires Python 3.11+ and a running local Docker engine. Use a fresh virtual environment: an older
install exposes the 2.x CLI.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install "agentbreeder[eval]==3.0.0a3"
.venv/bin/agentbreeder quickstart
```

[Install](/docs/install) covers uvx and npx and what has been verified on each platform. The demo
builds a sample image, deploys it, invokes it and removes it. It needs no model key; the sample
echoes JSON. If it stops, run `.venv/bin/agentbreeder doctor`.
