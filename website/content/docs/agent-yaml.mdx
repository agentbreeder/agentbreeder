```sh
agentbreeder new agent hello --model gemini      # writes agent.yaml, stack.yaml, prompt and evals
agentbreeder next hello                          # where the project is, and the command to run next
```

An `agent.yaml` says what an agent is made of: a runtime, a model alias, a prompt, knowledge,
tools, MCP servers, memory and evals. Each is a [registry](/docs/registry) reference
(`kind/name@X.Y.Z`). You write no agent Python: the runtime and the tool packages provide the
code.

It is not the [deploy manifest](/docs/manifest): `build` turns it into an image and a manifest,
which then deploy through the [identity gate](/docs/identity-gate). It is environment-neutral:
the model gateway, services, secret bindings and identities come from the operator config, and
nothing in the file can grant a permission or raise a limit.

```yaml
kind: agent
schema_version: 1
name: northwind-support
runtime: runtime/adk@1.3.0
model:
  alias: support-model         # a LiteLLM gateway alias
  reasoning: low
  max_model_calls: 4           # the last call has tools switched off
  budget_usd: 25               # can only lower the operator's ceiling
  rpm: 120
prompt: {ref: prompt/northwind-support@1.0.1}
knowledge:
  - {ref: knowledge/northwind-help@1.0.0, top_k: 5, extra_searches: 1}
tools:
  - {ref: tool/orders@1.0.0}
  - {ref: tool/customer-notes@1.0.0}
memory: {sessions: postgres, notes: true}
agent_events: postgres
traces: otlp
evals: {ref: eval/northwind-golden@1.0.1, threshold: 1.0, retries: 1}
```

Optional fields: `mcp:` ([MCP tools](/docs/mcp)), `guardrails:`
([Guardrails](/docs/guardrails)), and, on `main`, coming in 3.0.0a4, `subagents:`, `limits:` and
`skills:` on `runtime/adk@1.5.0` ([Sub-agents and skills](/docs/subagents-skills)). Also on
`main`, coming in 3.0.0a4: `runtime:` can pin a runtime for another framework (LangGraph, the
OpenAI Agents SDK, Deep Agents, CrewAI; see [Frameworks and runtimes](/docs/runtimes)), and
`registries:` names git repositories that hold registry versions ([Registry](/docs/registry)).

## Starting points

| Command | Writes |
|---|---|
| `new agent NAME --model gemini\|openai\|openrouter\|ollama\|anthropic` | a starter project: prompt, two eval cases, `stack.yaml`, gateway config, `agent.lock` (`anthropic` is config-only, not run; `ollama` ran on `runtime/adk@1.3.0` only) |
| `new agent NAME --from-spec FILE` | a project from the console's builder spec, with tools, knowledge and MCP servers |
| `new agent NAME --model PROVIDER --stack-for DIR/agent.yaml` | only `stack.yaml` and the gateway config beside an existing `agent.yaml` |
| `example northwind` | the Northwind example |
| `new agent NAME --runtime runtime/langgraph@1.0.0` | on `main`, coming in 3.0.0a4: the starter on another runtime; with Gemini on LangGraph it is verified (macOS), other runtimes are not ([Frameworks and runtimes](/docs/runtimes)) |
| `new agent NAME --model vertex --vertex-project P --vertex-location L` | on `main`, coming in 3.0.0a4: a plain starter for Vertex AI, config only, never run against Vertex ([Models and gateway](/docs/models)) |

`--from-spec` has run end to end with Gemini (prompt and evals, one knowledge version, one tool,
and both), OpenAI (with one knowledge version) and OpenRouter (prompt and evals). Two or more
tools and MCP servers have not. Provider status is on [Models and gateway](/docs/models).

## Build

```sh
agentbreeder build agent.yaml --stack . --environment dev [--locked]
```

`build` copies and hashes each ref into a build context, writes a data-only config, and runs
`docker build` with the runtime's fixed Dockerfile: a base image pinned by digest, hash-locked
requirements, no build arguments and no secrets. It writes the deploy manifest (and a candidate
manifest when the environment has a candidate identity) and never deploys. `agent.lock` records
every ref's hash; `--locked` refuses any change.

## The ADK runtime

`runtime/adk` is built on Google ADK and reaches models only through the stack's LiteLLM gateway.
It keeps sessions in Postgres, injects per-customer notes, runs hybrid pgvector and BM25
retrieval, loads tool packages, emits OpenInference traces and reads secrets only from mounted
files. Each version is immutable; newer ones add:

| Version | Adds |
|---|---|
| `1.1.0` | MCP tools through the stack's relay |
| `1.2.0` | each turn's `cost_usd`; tool events with agent, tool and latency |
| `1.3.0` | coded model errors with a correlation ID, bounded retries, `fallbacks` and `served_by` |
| `1.4.0` | `cached_prompt_tokens`, refused unknown tool names, `MODEL_BLOCKED` for a guardrail block |

The `new agent` starter writes `1.4.0`; Northwind is on `1.3.0`. Unknown-tool refusal in `1.4.0`
is covered by tests only: no model invented a tool name in the live run.

Tools run in the agent's process with its privileges. Customer scoping is enforced by the shipped
tools' own code, not by an engine boundary. Agents built this way can't run behind the opt-in MCP
egress sidecar yet.

## Try it before releasing

```sh
agentbreeder deploy deploy/hello-candidate.deploy.yaml --local --stack . --environment dev
agentbreeder invoke hello "When is support open?" --candidate --stack . --environment dev
agentbreeder eval agent.yaml --endpoint http://127.0.0.1:PORT --stack . --environment dev
```

Then [release](/docs/evals) it: `release` deploys a candidate, runs the eval set and promotes the
exact image only if it passes.

## Try it: Northwind

[`src/agentbreeder/examples/northwind`](https://github.com/agentbreeder/agentbreeder/tree/main/src/agentbreeder/examples/northwind)
is a customer support agent with knowledge search, memory, order lookup, staff-approved
cancellations, web search and escalation, about 35 lines of `agent.yaml`. Its services come from
its `stack.yaml` ([Backing services](/docs/services)). It needs `GEMINI_API_KEY` and
`TAVILY_API_KEY`; `OPENROUTER_API_KEY` is optional, for its fallback. A release (61 cases) and
six more turns came to about $0.26 in LiteLLM's estimate.

```sh
agentbreeder example northwind && cd northwind
agentbreeder services up . --environment dev --env-file ~/.env --yes
agentbreeder release agent.yaml --stack . --environment dev
```
