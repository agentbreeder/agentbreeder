## Findings

1. **The console drops the cause.** The CLI names `UPSTREAM_AUTH`, but the console's job row says
   only "Start services failed (exit 2)". The MCP grants screen says "Could not check upstream
   MCP_PROBE_FAILED". Neither says the credential was refused unless the log is opened.
2. **`next` reports "services up has not run for dev" after a run that started every container and
   failed at the probe.** The Home checklist repeats it. The containers stay running, and
   `services status` shows them.
3. **While the declared tools load, the revoke list labels granted tools "no longer declared".**
   On first opening Change a grant with Revoke selected, `get_me` and `list_issues` still showed
   "no longer declared" at least 2 s in (not timed), and "read" in the later flows. The label
   comes from `tool.effect || "no longer declared"` before the declared tools arrive.
4. **Layout:** in the Change a grant fieldsets, each checkbox or radio sits far from its label at
   1280 px (screenshot of step 3).
5. The fixture has no `agent.lock`, so `next` shows the build step as LOCK_STALE. This only
   matters once services pass.

### Repin (simulated drift)

GitHub's definitions didn't change during the run. To make a pinned definition differ from what
upstream serves, `drift.py` (in the session scratchpad) did three things in the sandbox only:
- appended " (older pinned wording, simulated drift)" to one tool's description in the relay's
  pins file (`~/.agentbreeder/stacks/<stack>/pins/github/pins.json`, replaced atomically; the
  directory is mounted read-only into the relay);
- recomputed that tool's hash;
- wrote the hash into `stack.lock`.

That is the state an upstream change would leave, with the pinned side changed instead of the
upstream side.
