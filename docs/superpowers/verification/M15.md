Status: **partial, with a STUB GitHub token** (wheel built from `main` at 01a0755, 2026-11-15, macOS 13.7.8

(`ghp_stub000…`, owner's instruction 2026-11-15: "just use stub for now"), so **no GitHub call
succeeded**. The relay did send the stub to GitHub's MCP endpoint during its probe, and GitHub

## Findings

1. **The console drops the cause.** The CLI names `UPSTREAM_AUTH`, but the console's job row says
   only "Start services failed (exit 2)". The MCP grants screen says "Could not check upstream
   MCP_PROBE_FAILED". Neither says the credential was refused unless the log is opened.
2. **`next` reports "services up has not run for dev" after a run that started every container and
   failed at the probe.** The Home checklist repeats it. The containers stay running, and
   `services status` shows them.
3. **While the declared tools load, the revoke list labels granted tools "no longer declared".**
   On first opening Change a grant with Revoke selected, `get_me` and `list_issues` still showed
   "no longer declared" at least 2 s in (not timed), and "read" in the later flows. The label
   comes from `tool.effect || "no longer declared"` before the declared tools arrive.
4. **Layout:** in the Change a grant fieldsets, each checkbox or radio sits far from its label at
   1280 px (screenshot of step 3).
5. The fixture has no `agent.lock`, so `next` shows the build step as LOCK_STALE. This only
   matters once services pass.

## Leak scan and teardown

The leak scan is the one in the M4 console addendum: the same sandbox, 187 files, 0 hits, read in
the terminal and not saved. It ran while this stack existed, before the teardown outputs were
written. Its needles were every `~/.env` value and every value in the sandbox's stack secret
files. A search of the relay's container log for `ghp_stub` found 0 hits (terminal, not saved;
the container is gone). A later grep of every saved output in the sandbox (203 files, the
teardown outputs included) for `ghp_stub` also found 0 hits. Screenshots were not text-scanned.

Teardown: `services down --purge --yes` for the stack (exit 0, 12.8 s). Afterwards containers,
volumes, networks and images equalled the pre-run snapshot (compared in the terminal, not saved). The relay image built by `services
up` was removed by the purge. The key file was deleted.
