The 90 s with no count matches the code, not a fault: conditions come from the `next` read, which
runs on a scope change, when a job ends and on window focus (`useGuide` in `app.js`; notifications
spec §1). Only stored events are polled every 20 s, and a `docker stop` stores no event (M11.md).
The rerun does not separate the two triggers (it changed scope and dispatched `focus`); that focus
alone refreshes the bell comes from reading the code, not from this run. A real return to the
window was not tested.

## S-02 from inside a container

Each request ran with `curl` in a `curlimages/curl:8.11.1` container, to
`http://host.docker.internal:8080`, with the console signed in and a password set. Bodies are quoted
in full (there is no token in them).

| Where | Request | Status | Body |
|---|---|---|---|
| Northwind's litellm container's network (`--network container:<litellm>`; it has no curl of its own) | `GET /api/overview` with `Host: 127.0.0.1:8080`, `X-AgentBreeder-Center: 1` | **401** | `{"data": null, "error": {"code": "SIGN_IN", "message": "Sign in again"}, "stale": false}` |
| the same | bare `GET /` | **403** | `{"data": null, "error": {"code": "FORBIDDEN", "message": "Bad host"}, "stale": false}` |
| the same | `GET /` with `Host: 127.0.0.1:8080` | 200 | the console's static `index.html` (the sign-in page; no data) |
| the same | `POST /api/session` with `Origin`, a wrong password, ×5 (04:27:18–21) | **403** ×5 | `{"code": "BAD_CREDENTIALS", "message": "Wrong email or password"}` |
| the same | the 6th and 7th | **429** | `{"data": {"retry_after": 30}, "error": {"code": "BACKOFF", "message": "Too many attempts. Wait 30 s, or press Enter in the terminal running `agentbreeder up` for a one-time link."}}` (then 29) |
| default bridge (`docker run --rm`) | the three GETs | 401, 403, 200 | the same bodies |
| Northwind's internal `-agents` network (where agents run) | the three GETs | curl exit 6 | no answer: `host.docker.internal` does not resolve there |

**The wait in the browser.** With the sign-in page open in Chrome, the script waited 32 s, then one
more wrong password from the container (04:28:41, about 80 s after the last 429 above) got 403 and the next six 429 with `retry_after` 60 (the wait doubled).
The right password typed in the browser then got **429**: "Too many attempts. Wait 56 s, or press
Enter in the terminal running `agentbreeder up` for a one-time link.", with Sign in disabled
([10](M2/10-backoff-in-browser.png)). After the wait, the right password signed in.

**Security events** after all of this (Settings, 20 newest rows, [11](M2/11-security-events.png)):
setup, sign-ins, the wrong passwords, "Password changed", "Session length changed", "Signed out
everywhere", "Password reset" (source **Terminal**), "Signed out of one tab", and one "Refused: too
many attempts" row per wait, not one per refused request (as the comment in `server.py` says,
so a flood cannot push other events out). No password or link appears.

Finding (#1180, not fixed here): every event that arrives over HTTP is recorded with source
`browser` (`server.py` passes the literal), so the container's guesses show as **Browser** in
Settings. The server records no peer address, so the label claims more than it knows.
