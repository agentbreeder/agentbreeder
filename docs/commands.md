# Focused rebuild reference

To use the published preview, install `"agentbreeder[eval]==3.0.0a2"` from PyPI (pip or uvx) or run `npx agentbreeder@3.0.0-alpha.2`; a bare `pip install agentbreeder` installs 2.x. `npx` and `uvx` leave no `agentbreeder` command on `PATH`; `uv tool install "agentbreeder[eval]==3.0.0a2"` adds one. See the root README. For development, use a fresh virtual environment in a checkout and install `python -m pip install -e ".[dev]"`. Run `agentbreeder --help`, `agentbreeder validate src/agentbreeder/examples/http-agent/agent.yaml`, `agentbreeder doctor`, `python -m pytest`, `ruff check src tests`, and `python -m build`. Implemented commands: `validate`, `doctor`, `deploy MANIFEST --local --environment ENV` (needs an operator config; see `identity-gate.md` and `first-deployment.md`), `status ID`, `remove ID --local`, `approve`/`reject`, `approve-call`/`reject-call`, `disable`/`enable`, `reconcile --local`, `audit list`/`audit verify`, `login`, `secret set NAME [--from-env VAR [--env-file FILE] | --generate [--force]]` (local secret files, see `local-deployment.md`), `registry new|publish|list|verify` and, on `main` (not in a published preview), the read-only `registry show`, `registry diff` and `registry used-by` (see `registry.md`), `quickstart [--dry-run]` (builds the shipped `http-agent` sample from a copy, passes it through a demo static-adapter identity gate, deploys, invokes, redeploys and removes it; history stays in a printed temporary directory; `--dry-run` runs `doctor` and `validate` only), `example list` and `example NAME [DIR]` (copy a shipped example, default `./NAME`; the copy is checked against the package's `_content.json`, and local state beside a checkout's examples is never copied), `validate` of agent files and of a `stack.yaml` (schema only; `services up` checks references), and `build`, `eval` and `release` (see `agent-yaml.md`). Local-only preview (#734): `services up|status|logs|env|down` start a project's `stack.yaml` backing services with Docker Compose and write a demo operator config under `~/.agentbreeder/stacks/` (see `services.md`); `--stack DIR` on `build`, `deploy`, `eval`, `release`, `status`, `remove` and `reconcile` uses it. `services up DIR --environment ENV [--locked | --update] [--env-file FILE] [--yes]` shows the grant and needs `--yes` when it is new or changed (`--update` accepts new hashes for edited project files such as an `init_sql`, never for a published service version); `services down [--volumes | --purge] --yes` deletes the stack's volumes, or with `--purge` everything `up` made (volumes, built service images, generated secrets, operator config and history). `doctor` also reports whether Compose v2 supports `up --wait` (a warning, not a failure). It also prints an INFO line when it finds 2.x state in `~/.agentbreeder` (names such as `state.json`, `workspace.yaml`, `registry/`; listed, never read); 3.x does not read or change it. Verified end to end with `src/agentbreeder/examples/northwind` (built-in `postgres-pgvector`, `litellm` and `phoenix`, two project services built from source, least-privilege database roles for the agent and the ops service; release 61/61, 2026-11-08 from a checkout and 2026-11-10 from PyPI `3.0.0a1`). `list` opens the local state read-only (no directory or database is created, no migration, no write lock, so it never blocks a running job); when the state is from an older version or an interrupted write left a journal, it says to run `agentbreeder migrate [--state-dir DIR | --stack DIR [--environment ENV]]`, which only upgrades the local state (no identity-provider calls; `status` re-verifies at the IdP and is not a substitute). `--stack DIR` no longer creates a stack directory for a stack that was never brought up (on `main`, not in a published preview). `logs --failed NAME [--state-dir DIR | --stack DIR [--environment ENV]] [--raw] [--json]` prints the redacted log tail `release` saved from its last failed candidate (see `agent-yaml.md`); it reads only that file. `services logs` now uses the same redactor (literal, base64, URL-quoted and JSON-escaped forms, URL passwords) and also redacts the stack's deployments' secret copies (on `main`, not in a published preview). `doctor` also checks, as advice only (never a failure), that the `agentbreeder` on `PATH` is this version: none is expected with npx or uvx (uv's temporary environment is skipped, so a stale install behind it is found), and a stale one from another install is named with the command to use instead. `cluster up` and `cluster down` hold a per-user lock (`~/.agentbreeder/locks/cluster.lock`, independent of `AGENTBREEDER_STACKS_DIR`); a second one at the same time fails with `CLUSTER_BUSY` (on `main`, not in a published preview). Commands that end a step print a `Next:` line in the form you launched with (`agentbreeder`, `npx agentbreeder@<ver>`, `uvx --from 'agentbreeder[eval]==<ver>' agentbreeder` or `python -m agentbreeder`), with the `--stack` and `--environment` they used; `build` points at `release`, never at a production `deploy` (on `main`, not in a published preview). `next [DIR] [--environment ENV] [--output DIR] [--json]` shows where a project is on the guided path and the one command to run next, reading only (state opened read-only, `DIR`'s stack state, one `compose ps`, no key values); text exits 1 while steps remain, `--json` prints the `next.md` contract and exits 0 (on `main`, not in a published preview). `new agent NAME --model gemini [--dir DIR] [--dry-run] [--json]` writes a starter project to `DIR` (default `./NAME`; it must not exist, or be an empty directory you own that others cannot write to, never a symlink): `agent.yaml` (`runtime/adk@1.0.6`, `traces: none`, `agent_events: none`, and a comment on the edit loop), `stack.yaml` (Postgres and LiteLLM, `chat` and `judge` aliases, a `DATABASE_URL` binding, `candidate: true`, `review_by` 180 days from today), `stack/litellm/config.yaml`, and the editable sources `src/prompt/` and `src/evals/` (the two eval cases run on 3.0.0a2, `retries: 1`); it publishes `prompt/NAME-prompt@0.1.0` and `eval/NAME-evals@0.1.0` into `DIR/registry` and writes `agent.lock`, so `build --locked` passes. Files are 0644 and directories 0755; on failure it removes what it wrote. `--model` is required and only `gemini` is offered (the only provider run end to end). `--dry-run` writes nothing; `--json` prints the files (path, mode, hash) and the published refs, and on a refusal `{"schema_version": 1, "error": {"code", "message"}}` (exit 2; argparse usage errors stay plain text). A group-writable existing `DIR` is accepted only off macOS and only for your own group. The template ran once end to end from a checkout on macOS (2026-11-12, `release` 2/2). To change the prompt: edit `src/prompt/prompt.md`, bump `version:` in `src/prompt/manifest.yaml`, `registry publish src/prompt`, change the ref in `agent.yaml`, then `build` and `release`. `quickstart` now ends with `Next: … new agent hello --model gemini`, and `next` offers `new agent` for a directory without `agent.yaml` (on `main`, not in a published preview). Run `agentbreeder COMMAND --help` for flags; see the root README for the demo.
