# Focused rebuild reference

To use the published preview, install `"agentbreeder[eval]==3.0.0a1"` from PyPI (pip or uvx) or run `npx agentbreeder@3.0.0-alpha.1`; a bare `pip install agentbreeder` installs 2.x. See the root README. For development, use a fresh virtual environment in a checkout and install `python -m pip install -e ".[dev]"`. Run `agentbreeder --help`, `agentbreeder validate src/agentbreeder/examples/http-agent/agent.yaml`, `agentbreeder doctor`, `python -m pytest`, `ruff check src tests`, and `python -m build`. Implemented commands: `validate`, `doctor`, `deploy MANIFEST --local --environment ENV` (needs an operator config; see `identity-gate.md` and `first-deployment.md`), `status ID`, `remove ID --local`, `approve`/`reject`, `approve-call`/`reject-call`, `disable`/`enable`, `reconcile --local`, `audit list`/`audit verify`, `login`, `secret set NAME [--from-env VAR [--env-file FILE] | --generate [--force]]` (local secret files, see `local-deployment.md`), `registry new|publish|list|verify` (see `registry.md`), `quickstart [--dry-run]` (builds the shipped `http-agent` sample from a copy, passes it through a demo static-adapter identity gate, deploys, invokes, redeploys and removes it; history stays in a printed temporary directory; `--dry-run` runs `doctor` and `validate` only), `example list` and `example NAME [DIR]` (copy a shipped example, default `./NAME`; the copy is checked against the package's `_content.json`, and local state beside a checkout's examples is never copied), `validate` of agent files and of a `stack.yaml` (schema only; `services up` checks references), and `build`, `eval` and `release` (see `agent-yaml.md`). Local-only preview (#734): `services up|status|logs|env|down` start a project's `stack.yaml` backing services with Docker Compose and write a demo operator config under `~/.agentbreeder/stacks/` (see `services.md`); `--stack DIR` on `build`, `deploy`, `eval`, `release`, `status`, `remove` and `reconcile` uses it. `services up DIR --environment ENV [--locked | --update] [--env-file FILE] [--yes]` shows the grant and needs `--yes` when it is new or changed (`--update` accepts new hashes for edited project files such as an `init_sql`, never for a published service version); `services down [--volumes | --purge] --yes` deletes the stack's volumes, or with `--purge` everything `up` made (volumes, built service images, generated secrets, operator config and history). `doctor` also reports whether Compose v2 supports `up --wait` (a warning, not a failure). It also prints an INFO line when it finds 2.x state in `~/.agentbreeder` (names such as `state.json`, `workspace.yaml`, `registry/`; listed, never read); 3.x does not read or change it. Verified end to end with `src/agentbreeder/examples/northwind` (built-in `postgres-pgvector`, `litellm` and `phoenix`, two project services built from source, least-privilege database roles for the agent and the ops service; release 61/61, 2026-11-08 from a checkout and 2026-11-10 from PyPI). Run `agentbreeder COMMAND --help` for flags; see the root README for the demo.
