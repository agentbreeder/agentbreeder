# `agentbreeder logs`

Show a local deployment's logs (redacted), or the saved tail of a failed candidate.

`logs --failed NAME [--state-dir DIR | --stack DIR [--environment ENV]] [--raw] [--json]` prints the redacted log tail `release` saved from its last failed candidate (see [`agent-yaml.md`](../agent-yaml.md)); it reads only that file.

`logs ID [--tail N] [--since D] [--follow] [--raw] [--json] [--state-dir DIR | --stack DIR [--environment ENV]]` prints a local deployment's container logs (stdout and stderr, timestamped; `--tail` default 200, at most 10 000; a 4 MiB cap) after Docker confirms the container is the recorded one, with every line redacted (the stack's stored secrets, every non-removed deployment's secret copies, `<state>/secrets`, URL passwords; Docker's 16 KiB partial records of a long line are joined first; best effort: a value transformed another way is not found, and values under 4 characters are not redacted; a value in a line over 16 KiB can be missed when the other stream's output lands between that line's parts) and nothing printed if a value could not be read, including when a deployment's secret copies are gone after a failed deploy (this also refuses a deployment with `model_access` whose gateway mints no per-deployment keys); controls are shown as visible escapes unless `--raw`. Logs can still contain customer messages and model output.

Visible escapes now also cover invisible format characters (#901): zero-width space, soft hyphen, BOM, word joiner and invisible operators (U+2060–U+2064), the deprecated format controls (U+206A–U+206F), the Mongolian vowel separator and the tag block (U+E0000–U+E007F, shown as `\UXXXXXXXX`), the same set the console escapes. Zero-width joiner and non-joiner stay as they are, since emoji and Persian and Indic text need them. This applies to every command that shows untrusted text with escapes (`logs`, `services logs`, `invoke`, `evals`, `events`, `usage`); one-line fields replace these characters with a space (on `main`, not in a published preview).

`--follow` streams until the container stops, Ctrl-C, SIGTERM, SIGHUP or, when stdin is not a terminal, the end of stdin (so `< /dev/null` ends it at once, with "Follow ended: stdin ended"), and stops its `docker logs` child (a SIGKILL of the CLI alone leaves it until its next write); a line over 1 MiB is dropped whole. `--follow --json` prints one JSON object per line (`schema_version`, `source`, `name`, `deployment`, `line`) and ends with `{"event": "end", "reason": "container|stdin|signal|interrupt", "dropped"}`, or with a one-line error object when `docker logs` failed.

For a Kubernetes (local `kind`) deployment, `logs ID` reads the `agent` container of one pod owned by the verified Deployment (through its ReplicaSets' owner references; a pod that merely carries the label is ignored), preferring a running pod, then the newest, with `kubectl logs pod/NAME -c agent`, through the cluster binding recorded with the deployment and after the same cluster, namespace and ownership checks (the pod lookup is scoped by the deployment's label; kubectl's stderr is never shown). A pod with no output yet returns no lines and its reason (a fixed Kubernetes word such as `ImagePullBackOff` or `Unschedulable`; `pod_reason` in `--json`, which also carries `target` and `previous` for both targets); a crash-looping pod is read and its reason shown; `--previous` shows the container before the last restart; `--follow` reads the chosen pod and ends when that pod goes away (`KUBECTL_LOGS_FAILED` when kubectl fails, `POD_NOT_RUNNING` when the pod has no output yet). The Kubernetes target runs no sidecar or egress container, so the agent container is the only source; only local single-user `kind` is supported.

Errors are `[CODE] message`, with `--json` also a JSON error object (on `main`, not in a published preview).

`logs ID` and `services logs` take `--level warning|error` to keep only records at that level or above, read per known format keyed by built-in ref (`service/postgres-pgvector`, including `FATAL` and `PANIC`; `service/litellm`; `service/phoenix`; `runtime/adk`) from `stack.lock` for a service and, for a deployment, from `--stack DIR`'s `deploy/NAME.build.json` when it records the runtime as built-in. A record's continuation lines (a traceback, Postgres `DETAIL`/`STATEMENT`, a multi-line SQL statement) keep its level, and a blank line ends a record unless the next line clearly continues it. It is a heuristic: project services, MCP relays and other images are unclassified, and `--level` on them fails with `LEVELS_UNAVAILABLE`. A container decides what its own lines look like, so `--level` can hide lines: it is a reading aid, not a completeness guarantee (hidden lines are redacted all the same). `--json` adds `format`, `levels` (one per line, null when unclassified) and `level`; `--follow --json` adds each line's `level` (on `main`, not in a published preview).

Flags: `agentbreeder logs --help`.
