# `agentbreeder registry`

Author and inspect registry versions.

Implemented: `registry new|publish|list|verify` and, on `main` (not in a published preview), the `skill` kind with `registry new skill NAME [--scripts]` (see [`registry.md`](../registry.md#skills-on-main-not-in-a-published-preview); `runtime/adk@1.5.0` loads skills without scripts), and, on `main` (not in a published preview), the read-only `registry show`, `registry diff` and `registry used-by`, plus `registry import PATH [--as NAME] [--version X.Y.Z]`, `registry fork REF [--as NAME] [--version X.Y.Z]` (copy a built-in or shared version into the project registry as a new version), `registry edit REF --set PATH FILE|--remove PATH [--bump patch|minor|major | --version X.Y.Z]` (change a project version's files and publish them as a new version) and `--dry-run`/`--expect-digest` on `publish`, `import`, `fork` and `edit` (see [`registry.md`](../registry.md)). To move `agent.yaml` to another version, see [`agent set-ref`](agent.md); `edit` prints that command only when `agent.yaml` declares `REF` and the command's dry run passes, and otherwise names the field to change in `agent.yaml` or `stack.yaml` (#990).

On `main`, not in a published preview: `list`, `show`, `diff` and `verify` also read `agent/` package versions, and `publish`, `import`, `fork`, `edit` and `new agent` refuse them (`PACKAGE_RELEASE_ONLY`, only `release` writes packages). See [Agent packages](../registry.md#agent-packages-in-progress-on-main-not-in-a-published-preview).

On `main`, not in a published preview: `publish`, `import`, `fork` and `edit` check a `tool/` version before writing it (allowed files only, no module that shadows the standard library, the runtime or its locked packages, every function resolving to a top-level `def` that parses; `TOOL_INVALID`), and `show` of a tool lists its functions with their `tool.yaml` parameters and Python signatures. See [Tool versions](../registry.md#editing-a-project-version-on-main-not-in-a-published-preview).

On `main`, not in a published preview (#1083 F1): `registry runtimes [--project DIR] [--json]` lists every `runtime/` version in the search roots with what the engine reads from it: its framework and display name, protocol and profile, capabilities, limits and reserved tool names, whether the version has been run end to end (today `runtime/adk@1.3.0` and `runtime/adk@1.4.0`, and on `main` `runtime/adk@1.5.0` and `runtime/langgraph@1.0.0`), and, for a version the engine cannot use, why. See [Runtime versions](../registry.md#runtime-versions-on-main-not-in-a-published-preview).

On `main`, not in a published preview (#1083 F2a): a runtime version that has a conformance report also shows `conformance: {passed, result, digest, date}` in `registry runtimes --json` (and `conformance passed|failed|incomplete` in the text): the newest report under `~/.agentbreeder/conformance/<name>/<version>/` for an image built on it. `passed` is true only for a report whose `result` is `pass`; an `incomplete` report is not a pass. A version with no report has no `conformance` key. See [`conformance`](conformance.md).

On `main`, not in a published preview (#829): `registry trust URL [--whole-host] [--private] [--yes]`, `registry trust --list [--json]` and `registry trust URL --remove` keep your trusted-source list in `~/.agentbreeder/sources.yaml`, which every fetch from a git registry source checks. See [Trusting a source](../registry.md#trusting-a-source).

On `main`, not in a published preview (#1085 S3): `registry conformance REF [--json]` prints the newest conformance report of a runtime version, whole: the newest under `~/.agentbreeder/conformance/<name>/<version>/` for an image built on it (the report `registry runtimes` summarises). `--json` prints `{"schema_version": 1, "ref", "report"}`, `report` null when there is none; text prints the report as `conformance` does, or `No conformance report for REF.` A ref that is not a pinned `runtime/` version is refused (exit 2, `REF_INVALID` or `REF_UNPINNED`). It reads no registry root, so the version does not need to be installed. See [`conformance`](conformance.md).

Flags: `agentbreeder registry --help`.
